# BudWatch Project

## Mission

BudWatch helps people discover the perfect movie for the kind of night they want.

The app is built around experiences, not ratings.

The first question BudWatch asks is never:

"What movie do you want to watch?"

Instead it asks:

"What kind of night are you having?"

Everything in the product should reinforce that philosophy.

---

# Product Pillars

1. Discovery over Search

Users should discover movies instead of endlessly scrolling.

2. Experiences over Reviews

Users log experiences.

They do not simply review movies.

3. Beautiful by Default

Every screen should feel premium.

Movie artwork should dominate the interface.

Typography should be large.

Spacing should breathe.

4. Community over Algorithms

People trust people.

Community experiences matter more than ratings.

5. Simplicity over Features

Avoid feature creep.

Every feature must make BudWatch easier or more enjoyable to use.

# Design Direction

Inspired by:

- Letterboxd
- Spotify
- Apple TV
- A24

Avoid:

- Generic Material Design
- Excessive gradients
- Visual clutter
- Meme aesthetics

---

# Visual Language

Dark UI.

Movie artwork first.

Large rounded cards.

Generous spacing.

Subtle motion.

Green is an accent.

Never the primary visual language.

# Engineering Philosophy

Reusable components.

TypeScript.

Feature-first architecture.

No duplicated UI.

Theme-driven styling.

Accessibility by default.

Performance matters.

Readability matters.

Maintainability matters.

---

# Definition of Done

A feature is complete only when:

- Works on iOS
- Works on Android
- Uses reusable components
- Matches the design system
- Has loading states
- Has error states
- Has accessible controls
- Passes TypeScript
- Feels premium
